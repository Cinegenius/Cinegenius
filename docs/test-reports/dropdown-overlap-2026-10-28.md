# Dropdown overlap correction — 2026-10-28

The profile hero uses an isolated stacking context. Its absolute `z-50` block/report menu was still below a subsequent profile image with its own positioned `z-10` content. Increasing only the menu's local z-index cannot escape that context. Other absolute menus could also be clipped by an ancestor's overflow.

Added `components/FloatingPanel.tsx` and the pure `lib/floating-panel-position.ts` positioning helper. Panels render into `document.body`, use fixed coordinates, clamp width/height to the visual viewport, choose above/below based on available room, and reserve space for the mobile bottom navigation. Resize/scroll/visual-viewport listeners and ResizeObserver keep the panel aligned. Outside pointer/focus and Escape close it; keyboard focus returns to the trigger after selection. The profile block/report menu (all profile variants), company actions, shared listing report button and shared occupation dropdown use this component. The old company header z-index/overflow workaround was removed. No content, authorization rules, report/block endpoints, or translated copy changed.

Verification: 688 automated tests passed; build, TypeScript, focused lint, localization/design checks and diff check passed. Four regression tests cover viewport positioning and all four shared-component integrations. An existing support test fixture was corrected to use timestamps relative to membership creation instead of a fixed calendar date, preserving its unread-state assertions at any execution time; this changes no production message behavior.

Interactive browser verification used the actual FloatingPanel and RoleDropdown, plus the exact BlockReportBar function extracted from ProfileView, in a temporary local fixture. The fixture deliberately reproduces an isolated header, an overlapping positioned photo surface, and an overflow-hidden field container. Desktop and 390px/820px iframe viewport simulations confirmed one menu at a time, `elementFromPoint` hitting the panel rather than the photo, in-viewport geometry, flipping above a bottom-edge trigger, report-reason selection without submitting, occupation search/selection, Escape and focus return. No real member was blocked or reported. These are browser simulations, not physical-device Safari tests.
